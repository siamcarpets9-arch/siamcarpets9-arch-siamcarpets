# Master Plan Gantt

ต้นแบบ Project ใหม่สำหรับ Workflow รับงานและจัดทำแผนการผลิตรวมแบบ Gantt

ฟังก์ชันในต้นแบบ:

- **ภาพรวมการผลิต (แท็บใหม่ `overview.js` / `overview.css`) — หน้าแรกของแอป**
  - สรุปว่าแต่ละ M/O · SO (ที่ฝ่ายขายเปิดแล้วทั้งหมด) อยู่แผนกไหน และกำลังทำหรือรอคิวอยู่ พร้อมการ์ดสรุปจำนวนต่อแผนก (วางแผน/ย้อมไหม/เจาะลาย/ส่งแผนกทอ/แผนกทอ/ตกแต่ง/เสร็จสิ้น) และตารางรายการทั้งหมด ค้นหา/กรองตามแผนกได้ คลิกแถวเพื่อไปหน้าที่เกี่ยวข้องได้ทันที
  - **ที่มาของสถานะ (สำคัญ):** งานที่ <u>เคย</u>บันทึกใบวางแผนงานในระบบนี้แล้ว (`plans[id].savedAt`) จะไล่เช็คข้อมูลจริงตามลำดับ วางแผน → เจาะลาย (`requisitionIssued`) → ส่งแผนกทอ (`issuedAt`) → แผนกทอ (`transferredToGlueAt` ต่อชิ้น) → ทากาวตกแต่ง (`receivedDate`/`finish.startDate`/มิติหลังอบแห้ง) เพื่อบอกแผนกปัจจุบันและสถานะกำลังทำ/รอคิวแบบสด — งานที่ <u>ยังไม่เคย</u>บันทึกแผนในระบบนี้ (ปัจจุบันคือเกือบทั้งหมด เพราะเพิ่งนำเข้าข้อมูลจริงและยังไม่มีใครบันทึกแผนจริงในระบบนี้) จะ fallback ไปแสดงตาม **`importStage`/`progress`** ที่นำเข้าจาก Google Sheet “QC Check Sheet” ของบริษัท (22 ก.ย. 2026) แทน — เป็นสถานะจริง ณ วันนำเข้า ไม่ใช่ข้อมูลสด จนกว่าฝ่ายต่าง ๆ จะเริ่มกรอกงานจริงในระบบนี้เอง (มีข้อความอธิบายเรื่องนี้แสดงอยู่ในหน้าเสมอ)
  - งานตัวอย่าง (`sample:true`) ที่ไม่มีทั้งข้อมูลนำเข้าและข้อมูลสด จะแสดงเป็น “รอวางแผน” เป็นค่าเริ่มต้น
  - **ปุ่มกรอง M/O · S/O:** เหนือตารางรายการมีปุ่มสลับ “ทั้งหมด / M/O / S/O” (พร้อมจำนวนกำกับ) ให้ดูรวมหรือแยกดูเฉพาะประเภทได้ทันที แต่ละแถวมีป้ายประเภทกำกับด้วย — แยกประเภทโดยเช็คจากฟิลด์ `type` ในเอกสารฝ่ายขาย (`SalesEngine`) เป็นหลัก ถ้าไม่พบเอกสารจะ fallback ดูจากคำนำหน้าเลขที่ (ขึ้นต้นด้วย “SO” = S/O, อื่น ๆ = M/O)
  - **แท็บ “Planning” (Master Plan Gantt) เดิมถูกย้ายมารวมอยู่ในหน้านี้แล้ว ไม่มีแท็บแยกอีกต่อไป** — เนื้อหา Gantt/KPI แผนกวางแผน/คำขอไหมเพิ่ม จะแสดงต่อท้ายด้านล่างของหน้า “ภาพรวมการผลิต” เสมอ (คั่นด้วยเส้นประ) เพื่อไม่ให้มี 2 หน้าที่ซ้ำซ้อนกัน

- Design Department จัดทำ ตรวจ และอนุมัติแบบ
- นำเข้าไฟล์ Excel ได้ทั้งแบบเลือกชีตเดียวหรือทุกชีต
- รองรับหัวตาราง: วันที่รับงาน, กำหนดส่งงาน, เกรด, Design No., Description, Customer, Project, Designer, วันที่ส่งงาน, หมายเหตุ
- กรอก Design Request เองผ่านฟอร์มในหน้า Design
- Design KPI: งานรับเข้า, ส่งงานแล้ว, งานค้าง, งานเกินกำหนด, Lead time เฉลี่ย และจำนวน Designer
- ตัวกรอง KPI ราย Designer ตามทุกช่วงเวลา รายเดือน รายไตรมาส และรายปี
- **ต้นทุน Design (แท็บใหม่ `cost.js` / `cost.css`)**
  - ต้นทุนต่อ Project = ค่าแรงทำแบบ (เวลาปกติ + โอที + วันหยุด) + ค่าออกวัดพื้นที่ · แสดงจำนวนแบบ (ใหม่ / แก้ไข -01↑) และต้นทุนต่อแบบ
  - ค่าแรง = เงินเดือน ÷ (วันทำงาน/เดือน × ชม./วัน); โอที = เงินเดือน ÷ (30 × ชม./วัน) × ตัวคูณ (ตั้งค่าได้ทั้งหมด)
  - ตัวประมาณเวลาอัตโนมัติ: ชั่วโมงมาตรฐานต่อประเภทงาน (ทำแบบ/Layout/Clean/แก้แบบ/แก้สี/SO) จัดลงวันทำงานของ Designer — 8 ชม./วันเป็นเวลาปกติ ส่วนที่เกินตามกำหนดส่งเป็นโอที/วันหยุด · กรอกชั่วโมงจริงทับรายแบบได้
  - ทริปออกวัดพื้นที่: บันทึกวัน เวลาออก–กลับ ผู้ไป ค่าน้ำมัน/ทางด่วน/ที่พัก/อาหาร/อื่น ๆ → แยกปกติ/โอที/วันหยุดอัตโนมัติ (หักพักเที่ยง) และหักเวลาว่างของ Designer ในวันนั้น
  - Sale ผู้ดำเนินการ: จับคู่ Customer → Sale ในหน้าตั้งค่า แก้รายโครงการได้ในตาราง (หน้า Sales ใช้ชื่อ Sale นี้ด้วย) · สรุปต้นทุนตาม Sale และตาม Designer
  - กรองรายเดือน/ไตรมาส/ปี · ข้อสังเกตอัตโนมัติ · ค่าตั้งต้นของเงินเดือนเป็นค่าสมมติ ต้องกรอกจริงในตั้งค่า
- **รายงานฝ่ายขาย (แท็บใหม่ `sales.js` / `sales.css`)** — Design อนุมัติแล้วส่งให้ฝ่ายขายเปิดใบงาน
  - กด “เปิด Job · ออกเลข M/O” ในหน้า Sales → ฟอร์มเปิด M/O (ดึงลูกค้า/Project/Design No. มาให้) → บันทึกแล้วจึงส่ง Planning และแสดงเลข M/O ในหน้า Sales · “+ SO ตัวอย่าง” ออกเลข SO แยกอิสระ ไม่บล็อกการเปิด M/O
  - รายงานแยก 2 ตลาด: **ต่างประเทศ** (USD) และ **ในประเทศ** (THB) แยกตาราง แยกยอด
  - เลข run 4 ชุด แก้ไขได้: ต่างประเทศ `MO 0001/26` · `SO SC 0001/26` / ในประเทศ `MO TH 001/26` · `SO D001/26` — ระบบเสนอเลขถัดไป (เลขสูงสุดของปี + 1) แก้ในฟอร์มได้ทุกใบ, ตั้ง Prefix / จำนวนหลัก / “เลขถัดไป” ได้ที่ปุ่ม “ตั้งค่าเลข run”
  - M/O หลายรายการใช้เลขเดียวกันได้: ใส่เลขที่ซ้ำแล้วระบบถามว่าจะรวมรายการเข้า M/O เดิมหรือไม่ · SO มีสถานะ ร่าง → ส่งลูกค้า → Approved / ไม่อนุมัติ
  - นำเข้า Excel รายงาน M/O (ชีต 2026 Current): แถวย่อยที่ไม่มีเลข M/O รวมเข้า M/O ก่อนหน้า, แถวหน่วย F2 แปลงเป็น ตร.ม. (ใช้แถวแปลงเมตรในไฟล์ ถ้าไม่มีใช้ × 0.09290304), ข้ามแถว “To Convert” / แถวสรุป, ซ่อมวันที่ที่ Excel สลับวัน/เดือน (เลือกโหมดอื่นได้)
  - KPI ฝ่ายขาย กรองปี / เดือน / วัน: **รับเข้า (ตร.ม.)** = ตามวันเปิด M/O · **ส่งออก (ตร.ม.)** = ตามวัน Postpone (ถ้ามี) หรือ Dispatch, หรือ “วันส่งจริง” ที่กดยืนยัน (แทนวัน Dispatch) · ยอดขาย = ยอดรวม M/O ตามวันเปิด · มูลค่าส่งออก · SO Approved/ทั้งหมด · ตารางรายเดือน (คลิกแถวเพื่อกรอง) และรายวัน
  - Dispatch ที่ระบุเฉพาะเดือนนับในยอดรายเดือน แต่ไม่นับในรายวัน (แสดงเป็นแถว “ไม่ระบุวัน”) · ใส่เรต USD→THB (ไม่บังคับ) เพื่อแสดงยอดเทียบเป็นบาท
  - **ยอดขายแยก Sale:** ตารางสรุป Sale (M/O เปิด, รับเข้า ตร.ม., ยอดขาย + สัดส่วน, ส่งออก, มูลค่าส่งออก, SO) ตามช่วงเวลาที่เลือก และตารางรายเดือนแยก Sale (เลือกตัวชี้วัดได้) · คลิกแถว Sale หรือเลือกช่อง “Sale” เพื่อกรองทั้งหน้า (KPI / รายเดือน / รายวัน / ทะเบียน)
  - Sale ของแต่ละ M/O/SO ใช้ลำดับ: ที่ระบุรายใบ (ช่อง Sale ในตารางทะเบียนหรือฟอร์ม) → Sale ของ Design ที่เชื่อมอยู่ → จับคู่ลูกค้า → Sale (ปุ่ม “Sale ผู้ดำเนินการ”) → ตารางลูกค้า → Sale ของหน้า “ต้นทุน Design” ที่ชื่อลูกค้าตรงกัน · ยังไม่ระบุจะรวมเป็น “ไม่ระบุ Sale”
  - นำเข้าซ้ำจะแทนที่เฉพาะ M/O ที่นำเข้าและยังไม่ถูกแก้ไข (M/O ที่แก้ไข/ยืนยันวันส่งแล้วจะคงไว้) · ดาวน์โหลดสรุปรายเดือน/รายวัน/รายการ M/O/SO เป็น Excel
- **เครื่องคำนวณ (แท็บ “เครื่องคำนวณ” `calc.js` / `calc.css`)** — ใช้สูตรจากไฟล์และภาพที่ให้มา
  - **ฟุต/นิ้ว → ตร.ม.:** 1 ฟุต = 30.48 ซม., 1 นิ้ว = 2.54 ซม. (กว้าง × ยาว × จำนวนชิ้น) เช่น 8'3" × 30'6" = 251.46 × 929.64 ซม. = 23.38 ตร.ม. · มีช่องแปลงเร็ว ฟุต ↔ เมตร
  - **วงกลม:** π r² (ค่าเริ่มต้น π = 22/7 ตามตัวอย่าง) + เผื่อ 10% — Ø 3.05 ม. = 7.31 + 0.73 = 8.04 ตร.ม. · **วงรี:** π·D·d/4 (π = 3.14) — 3.40 × 2.80 ม. = 7.47 ตร.ม. (ค่า π และ % เผื่อแก้ได้)
  - **Blank area:** พื้นที่แบบ = กว้าง × ยาว, พื้นที่ Blank = พื้นที่แบบ × %, พื้นที่จริง = แบบ − Blank (2.10 × 2.10 ม., 21.46% → 4.41 / 0.95 / 3.46) · กรอกเป็น % หรือเป็นพื้นที่ก็ได้
  - **ม้วนพรม:** ความหนา t = ขนพรม + backing (มม.), เส้นผ่านศูนย์กลางรอบที่ n = D₀ + 2·n·t/10 (ซม.), ความยาวสะสม L = (π/100)·(n·D₀ + t′·n(n+1)) เมื่อ t′ = t/10 ซม. · ใส่ความยาวเพื่อหาจำนวนรอบ/เส้นผ่านศูนย์กลาง หรือใส่เส้นผ่านศูนย์กลางเพื่อหาความยาว + ตารางรอบ 1–N ตรวจกับชีต “วิธีการคำนวณพรมเวลาม้วน” แล้ว คลาดเคลื่อนสูงสุด 0.005 ม. (ชีตต้นฉบับมีค่า 0.1 ซม. ผิดที่รอบ 18)
- **โค้ดสี POM (แท็บ “โค้ดสี” `colors.js` / `colors.css`)** — ตรวจสีของแบบว่าตรงกับโค้ดสีหรือไม่
  - ชุดที่อ่านกฎจากรูปกล่องได้: **SIAM 5–8** (5001–8908 = กล่อง 5/6/7/8 · แถว 0–9 · คอลัมน์ 1–8) และ **CC001–CC360** (คอลัมน์ 1–36 × แถว A–J เช่น CC012 = 2B) — ระบบบอกกล่อง/ตำแหน่ง และแจ้งโค้ดที่ไม่ถูกต้อง (เช่น 6009, CC400)
  - ชุดอื่น (ARS 600/320, INNO & SIAM, LOOP HOUSE ฯลฯ) ไม่มีตารางโค้ดในไฟล์ ต้องเพิ่มโค้ดเองหรือนำเข้า Excel/CSV (คอลัมน์ code, series, name, hex, tone, year, note) · ชีต SIAM 1–4 / ARS1 / THAIPING / STOFF ในไฟล์ต้นฉบับว่าง
  - **ARS 600 / ARS 320:** ค้นข้อมูลจากเว็บผู้ผลิต (ARS Colors, arscolors.com — ดูแหล่งอ้างอิงท้ายไฟล์) พบว่า “ARS 600” ตรงกับระบบ **ARS 600 Wool** (ไหมขนสัตว์ 600 สี รุ่นแรกของบริษัท ก่อตั้งปี 2001) และ “ARS 320” ตรงกับ **ARS 320 Viscose** (ไหมเรยอน 320 สี จัดเป็น 16 กลุ่มสี ตัวอักษร A–P × 20 โทนต่อกลุ่ม เช่น 20P, 01A) — ระบบจึงช่วย **เดาโทน/กลุ่มสีของโค้ด ARS 320** ให้เป็นคำใบ้เมื่อพิมพ์ตรวจ (ไม่ตัดสินว่าถูก/ผิด และไม่ทำเป็นกฎบังคับเหมือน SIAM/CC เพราะเป็นข้อมูลจากเว็บ ไม่ใช่จากกล่องจริงของโรงงาน) — โปรดเทียบกับกล่องจริงก่อนใช้งานจริง
  - แต่ละโค้ดในทะเบียนบันทึกเพิ่มได้ 2 ช่อง: **โทนสี** (เช่น น้ำตาล, เบจ/ครีม, เทา ฯลฯ) และ **ปีของการ์ดสี** (ปีของแค็ตตาล็อก/การ์ดตัวอย่างที่ใช้เทียบโค้ดนี้ — มีประโยชน์เพราะผู้ผลิตออกการ์ดสีใหม่เป็นรุ่น ๆ เลขโค้ดเดียวกันอาจเพี้ยนสีต่างรุ่นได้) ค้นหาในทะเบียนได้ทั้งโทนและปี
  - **ไม่มีค่าสีของช่องในรูปถ่าย** — ระบบไม่เดาค่าสีจากภาพ: ค่า hex อ้างอิงต้องใส่เองหรือนำเข้า จึงจะเทียบสีของแบบได้ (ΔE CIEDE2000: ≤ 3 ตรง, ≤ 6 ใกล้เคียง, > 6 ต่าง — ปรับเกณฑ์ใน `colors.js` ตัวแปร `DE_OK` / `DE_NEAR`) · ถ้ายังไม่มีสีอ้างอิง ระบบตรวจได้แค่ว่าโค้ดมีจริงและอยู่ตำแหน่งไหน
  - เก็บรูปกล่องอ้างอิงไว้ในโฟลเดอร์ `pom/` (คลิกดูขยายได้) · ทะเบียนเก็บใน localStorage (`enterprise-color-registry`) ดาวน์โหลดเป็น CSV ได้
- **ใบ M/O A3 หน้า 1–2 (`moform.js` / `moform.css` + `moform-p1.svg`, `moform-p2.svg`)** — ส่ง Planning
  - หน้าต่างเปิด/แก้ไข M/O มีส่วน “ข้อมูลใบ M/O A3 สำหรับ Planning”: Ref S/O, Product Code, กำหนดส่ง, Specs (TYPE, Yarn, Pile, Surface A–F, Backing, Label, Packing), รายการสี (โค้ดสี Matching, ชื่อ, สีของแบบ, ก.ก., DL/F/I, ย้อม/จ้าง, รายละเอียดกรอ-ตีเกลียว) — ช่องโค้ดสีตรวจกับทะเบียนทันที
  - ปุ่ม “ใบ M/O A3” ในตาราง M/O (หรือ “ดูตัวอย่าง / พิมพ์” ในหน้าต่างแก้ไข) เปิดหน้าตัวอย่าง 2 หน้า A3 แนวนอน เติมอัตโนมัติจาก M/O: เลขที่, ลูกค้า, Project, ตร.ม. รวม, จำนวนชิ้น, รายละเอียดแบบ, คุณภาพ, Design No., กำหนดส่ง (Dispatch/Postpone ล่าสุด), จำนวนสี, ช่องติ๊ก Specs, ตารางสี, กล่อง “คำนวณพื้นที่” (ขนาดและ ตร.ม. ต่อรายการ), Remark, หน้า 2 (PO#, M/O#, CUSTOMER, สี/ก.ก. แยกย้อม-จ้าง, รวม, นน./ตร.ม., ช่อง QC ที่ตรงกับสเปก)

- **ใบวางแผนงาน (แท็บ “ใบวางแผนงาน” `planning.js` / `planning.css`)** — แผนกวางแผนรับใบงานจากฝ่ายขาย → กำหนด spec การทอ → คำนวณน้ำหนักไหมสั่งย้อม → คำนวณระยะเวลาผลิต → บันทึกเข้า Master Plan Gantt
  - สูตร/ตารางทั้งหมดตรวจสอบกับไฟล์จริงของฝ่ายผลิต 2 ไฟล์ (`ฟอร์มคำนวณไหม.xlsx`, `เกรดการทอ แต่ง.xlsx`) ไม่ใช่ตัวเลขประมาณ
  - **1) ข้อมูลงาน:** เลือก Job ที่ฝ่ายขายเปิดแล้ว (M/O เลข, ลูกค้า, Project ดึงมาให้อัตโนมัติ) · พื้นที่รวมดึงจากผลรวม ตร.ม. ของรายการใน M/O นั้น (แก้ไขเองได้ถ้ายังไม่ตรง)
  - **2) กำหนด Spec การทอ:** กรอก “% พื้นที่มีลวดลาย” ค่าเดียว ระบบแนะนำเกรด (A–Z) ให้ทั้ง 3 แผนก (ทอ/ตอกลาย-ขยายลาย/ตกแต่ง) ตามตารางประสิทธิภาพจริงของฝ่ายผลิต พร้อมแจ้ง Max จำนวนสี, ข้อจำกัด Cut+Loop ผืนเดียวกัน, ระดับความยาก (ก้าว), อัตรา ตร.ม./ชม./คน และค่าแรงต่อเกรด — override เป็นเกรดใดก็ได้ถ้าจำเป็น
  - **3) คำนวณน้ำหนักไหมสั่งย้อม:** แบ่งพื้นที่ดีไซน์เป็น “โซน” ตามเทคนิคทอ (Loop / Tip Shear / Cut to Side / Cut to Cut) แต่ละโซนกรอกเป็น % หรือ ตร.ม. + เลือกชนิดไหม + คุณภาพจาก Preset (หรือกรอก Stitch/Row/Pile Height/Tex/จำนวนเส้นไหมเองได้ทุกช่อง)
    - **สูตรน้ำหนัก/ตร.ม.** มาจากไฟล์ “ฟอร์มคำนวณไหม.xlsx” ชีต Tufting Spec. โดยตรง (ไม่ใช่ตารางค่าคงที่): CUT ใช้ Fin/Tuft Pile Length = (100/Stitch)+0.8+(ความสูง×2), น้ำหนัก = Stitch×Row×ความยาว×Tex×จำนวนเส้นไหม/5000; LOOP บวกอีก +1 ในสูตรความยาว — ตรวจแล้วตรงกับตาราง “ชนิด/คุณภาพ→น้ำหนัก” ในไฟล์จริงทุกค่า (เช่น HWO 45C = 2694 ก./ตร.ม., HWO 45L = 2387 ก./ตร.ม.)
    - ★ **กฎย้อมที่ยืนยันแล้ว:** น้ำหนักที่ใช้สั่งย้อมของโซน Cut/Tip Shear คำนวณจาก Tuft Pile Height (ความสูงก่อนเจียร์) เสมอ แม้บางเอกสารเรียกชื่อคอลัมน์ต่างกัน — ถอดสูตรย้อนกลับแล้วตรงกับตัวอย่างที่ยืนยัน (HBBVC 45C, Tex 360, 4 เส้น → 2.552 กก./ตร.ม.) พอดี
    - **จัดหม้อย้อมอัตโนมัติ:** โซน Loop + Tip Shear รวมหม้อเดียวกันได้ (ค่าเริ่มต้น) ส่วน Cut to Side และ Cut to Cut แยกหม้อเด็ดขาดจากกันและจากหม้อ Loop/Tip Shear เสมอ (ระบุรหัสสีต่อโซนเพื่อแยก/รวมหม้อเพิ่มเติมได้) · บวกเผื่อ % ปรับได้ต่อแผน (ค่าเริ่มต้นอ้างอิงไฟล์จริง 10%)
  - **4) กำลังคนและระยะเวลาผลิต:** วัน = พื้นที่ ÷ (อัตรา ตร.ม./ชม./คน ตามเกรด × ชม.ทำงาน/วัน × จำนวนคน) ต่อเนื่องกันเป็น Master Plan (ตอกลาย/ขยายลาย → ย้อม (Lead time ปรับได้) → ทอ → ตกแต่ง → ตรวจ/แพ็ค/สโตร์) พร้อมวันที่เริ่ม-เสร็จจริงต่อแผนก
  - **5) ใบสั่งย้อม (Dye Order):** ต่อยอดจากหม้อย้อมในข้อ 3 อัตโนมัติ — 1 การ์ด ต่อ 1 หม้อย้อม กรอกได้ครบ: แหล่งย้อม (ภายในบริษัท/จ้างบริษัทอื่น + ชื่อผู้รับจ้าง), Yarn Lot, วิธีย้อม (Cone to Cone / Hank / Package / อื่น ๆ), ต้องกรอ/ทวิส/ควบไหมหรือไม่, วันที่เปิดใบสั่งย้อมและวันที่ต้องการไหม
    - **วันที่ผูกกับ Master Plan อัตโนมัติ:** ค่าเริ่มต้นดึงจากกำหนดการ “สั่งย้อมไหม” ในข้อ 4 (เริ่ม/จบของแผนก Dyeing) ทุกครั้งที่ตารางเวลาเปลี่ยน — แก้วันที่เองได้ แต่ระบบจะเตือน “⚠ ไม่ตรงกับ Master Plan” ทันทีถ้าค่าที่แก้ไม่ตรงกับกำหนดการจริง
    - **ต้นทุนกรณีจ้างย้อมภายนอก:** คิดจาก ค่าไหม (ถ้าติ๊ก “บริษัทซื้อไหมเอง” × ราคา/กก.) + ค่าจ้างย้อม (บาท/กก.) + surcharge % (ถ้าติ๊ก “ไหมชนิดพิเศษ”, คิดจากยอดไหม+ค่าจ้างย้อม) + ค่าควบ/ค่ากรอ/ค่าทวิส (บาท/กก., ปรากฏเมื่อติ๊กช่องนั้น ๆ) + ค่า Hank (บาท/กก., เฉพาะเลือกวิธีย้อม Hank) + ภาษี EPZ % (คิดจากยอดรวมก่อนภาษี) รวมเป็นยอดต่อหม้อ และรวมทั้งใบด้านล่าง — ย้อมภายในบริษัทไม่คิดค่าใช้จ่ายกลุ่มนี้ (แสดงเฉพาะ “ไม่คิดค่าจ้างย้อม/surcharge ภายนอก”)
    - **สำคัญ — ยังไม่มีข้อมูลราคาจริง:** อัตราทุกช่อง (ราคาไหม/กก., ค่าจ้างย้อม/กก., ค่ากรอ-ทวิส-ควบ/กก., ค่า Hank/กก., % surcharge, % ภาษี EPZ) ตั้งต้นที่ 0 ทั้งหมด เพราะไม่มีไฟล์ต้นทางยืนยันราคาจริง ต้องกรอกเองต่อออเดอร์/ผู้รับจ้างย้อมแต่ละราย
  - **6) ต้นทุนแรงงานโดยประมาณ:** พื้นที่ × ค่าแรงต่อเกรด (800–1,200 บาท ตามเกรดทอ) + ค่าแต่ง/ทากาว (400 บาทคงที่) — **สมมติฐาน:** ตัวเลขในตารางต้นฉบับเป็น “บาท/ตร.ม.” โปรดยืนยันหน่วยจริงกับฝ่ายบัญชี/ฝ่ายผลิตก่อนใช้อ้างอิงจริง · แสดงรายชื่อพนักงานทอ/ตกแต่ง 16 คนตามรายการที่ให้มา ใช้อ้างอิงจำนวนหัวทอ/กำลังคน
  - กด “บันทึกแผนและส่งเข้า Master Plan Gantt” → แทนที่แถวเดิมของ Job นั้นด้วยตารางเวลาที่คำนวณจริง 5 แผนก (Production/Dyeing/Weaving/Finishing/Store) ในหน้า Planning ทันที · บันทึกแผน (รวมข้อมูลใบสั่งย้อมทุกใบ) ไว้ใน localStorage (`siam-planning-worksheets`) เปิดกลับมาแก้ไขได้ · จำวันที่เสร็จตาม Plan (`scheduleEndDate`) ไว้ใช้ตัดสิน KPI ส่งตรงตามกำหนด
- **ส่งแผนกทอ + Surplus ไหม + KPI แผนกวางแผน (แท็บ “ส่งแผนกทอ” `weaving.js`)** — ขั้นถัดจากใบวางแผนงาน ก่อนขึ้นทอจริง
  - **วัตถุดิบก่อนขึ้นทอ:** แผนกทอขึ้นทอได้ก็ต่อเมื่อครบ 3 อย่าง — (1) ไหมจากแผนกย้อม (ติ๊ก “รับไหมย้อมแล้ว” ต่อหม้อย้อม), (2) ไหม Surplus ที่ดึงมาใช้ (ถ้ามี — ระบบเช็คอัตโนมัติว่าไม่เกินยอดคงเหลือในคลัง), (3) ผ้าใบสำหรับทอจากแผนกดีไซน์/ขยายลาย (ติ๊กครั้งเดียวต่อ M/O) — ปุ่ม “ออกใบส่งแผนกทอ” จะกดได้ก็ต่อเมื่อครบทั้ง 3 อย่างเท่านั้น
  - **ไหม Surplus:** ถ้าดึงจากคลัง Surplus มาใช้ ระบบจะบวกเข้าไปในยอด “รวมส่งมอบ” ของหม้อย้อมนั้นให้อัตโนมัติ (ยอดส่งมอบจริง = ไหมจากแผนกย้อม + ไหม Surplus ที่ดึงมาใช้) ตามที่ระบุไว้
  - **กำหนดคนทอ + เกรดต่อชิ้น:** ดึงรายการชิ้น/Location จาก M/O จริง (ถ้ามี) ให้กำหนดจำนวนคนทอและเกรดแยกต่อชิ้นได้ (ค่าเริ่มต้นดึงจากใบวางแผนงาน)
  - **รายงานไหมเหลือ/ขอไหมเพิ่มหลังทอ:** กรอกน้ำหนักไหมที่ใช้จริงต่อหม้อย้อม ระบบคำนวณส่วนต่างจากยอดที่ส่งมอบให้อัตโนมัติ — **เหลือ** เข้าคลัง Surplus ไหมทันที (ดึงไปใช้กับ M/O อื่นที่สี/ชนิดไหม/Tex ตรงกันได้), **ขาด** บันทึกเป็นรายการขอย้อมเพิ่ม (ลบออกจากคลัง Surplus ของบัคเก็ตนั้น) — เก็บ log ไว้ทุกรายการ พร้อมวันที่
  - **คลังไหม Surplus คงเหลือ (รวมทุก M/O):** ตารางสรุปยอดคงเหลือต่อ (ชนิดไหม, รหัสสี, Tex) ทุกครั้งที่มีรายงานไหมเหลือ/ขาดจาก M/O ใดก็ตาม เก็บใน localStorage (`siam-yarn-surplus`)
  - **KPI แผนกวางแผน (แสดงในหน้า Planning เดิม):** การ์ด “M/O รับเข้า (Planning)” = จำนวน M/O ที่บันทึกใบวางแผนงานแล้ว และ “KPI ส่งตรงตามกำหนด” = % ที่ส่งตรงเทียบกับที่วางแผนไว้ พร้อมตาราง “KPI แผนกวางแผน — ส่งตรงตามกำหนด” แสดงราย M/O — **วันส่งจริงตัดจากฝ่ายขาย**: M/O จะถูกนับว่า “ส่งแล้ว” ก็ต่อเมื่อมีทั้งเลข **INV** และ **วันที่ยืนยันส่งจริง** (ปุ่ม “ยืนยันส่ง” ในหน้ารายงานขาย) ครบทั้งคู่ แล้วเทียบกับวันที่ Planning วางแผนไว้ (`scheduleEndDate` จากใบวางแผนงาน) — ตรงหรือเร็วกว่า = “ส่งตรงตามกำหนด”, ช้ากว่า = “ส่งล่าช้า”, ยังไม่มี INV/วันส่งจริง = “รอส่ง/รอ INV” (ยังไม่นับในอัตราผ่าน)
  - คุณภาพ/ชนิดไหมที่ยืนยันสูตรแล้วในเวอร์ชันนี้: **HWO (WO 380/1)** ครบ 8 ความสูง × Cut/Loop (16 โค้ด, Tex 380) และ **HBBVC 45C** (Bamboo Viscose, Tex 360) — คุณภาพอื่นให้กรอกพารามิเตอร์เอง (Stitch/Row/Pile Height/Tex/จำนวนเส้นไหม) ต่อรายการจนกว่าจะเพิ่ม Preset ยืนยันแล้วเพิ่มเติม (แก้ไขทะเบียน Preset ได้ที่ `localStorage: siam-quality-presets`)
- **แผนกเจาะลาย/ขยายลาย (แท็บ “เจาะลาย/ขยายลาย” `pattern.js`)** — รับใบสั่งจากแผนกวางแผนหลังบันทึกใบวางแผนงานแล้ว (Job เดียวกับหน้าอื่น ๆ) อยู่ก่อนขั้น “ส่งแผนกทอ” ใน Master Plan
  - **รายชื่อพนักงานแผนกเจาะลาย/ขยายลาย:** การ์ดจัดการรายชื่อพนักงาน (เพิ่ม/ลบได้อิสระ ไม่ผูกกับ Job ใดเป็นการเฉพาะ — เพิ่มครั้งเดียวใช้ซ้ำได้ทุกใบสั่ง) กันชื่อซ้ำอัตโนมัติ เก็บแยกต่างหากจากทะเบียนพนักงานทอ/ตกแต่งในหน้า Planning (`localStorage: siam-workforce-pattern`) เพราะเป็นคนละแผนก — **ไม่มีรายชื่อตั้งต้นให้ (ไม่มีข้อมูลจริง) ต้องกรอกรายชื่อจริงของแผนกเองในหน้านี้ก่อนใช้งาน**
  - **ใบสั่งเจาะลาย/ขยายลาย:** ดึงเกรดและระยะเวลาจากใบวางแผนงานของ Job นั้นโดยตรง (ตารางประสิทธิภาพ `PUNCH_GRADES` ชุดเดียวกับหน้า Planning — 5 เกรด A&B/C/D/E×ฆ้อน หรือ E×เครื่องเจาะ) วันที่รับงาน/วันที่เสร็จอ่านจากช่วง “Production” จริงใน Master Plan Gantt (ไม่คำนวณซ้ำ) — มีช่อง “ผู้รับผิดชอบปั๊มผ้า/เจาะลาย” เป็น**ติ๊กเลือกได้หลายคน** (ปั๊มผ้าปกติมีคนทำงานพร้อมกันหลายคนต่อผืน) จากรายชื่อพนักงานด้านบน แสดงสรุปจำนวนและรายชื่อที่มอบหมายไว้ใต้ช่องติ๊ก เพิ่ม/ถอดคนภายหลังได้อิสระโดยไม่กระทบสถานะใบเบิก Store
  - **คำนวณผ้าใบ:** กรอกความกว้าง/ความยาวของแบบ (ม.) + ค่าเผื่อขึงผ้าด้านข้าง และหัว-ท้าย (ม./ฝั่ง) ระบบคำนวณ ความกว้างที่ต้องใช้ = ความกว้างแบบ + เผื่อข้าง×2, ความยาวที่ต้องใช้ = ความยาวแบบ + เผื่อหัวท้าย×2 แล้วเลือกหน้าผ้าใบที่มีจริง (**3 / 5 / 6 เมตร**) โดยเลือกหน้าแคบที่สุดที่ยังพอ พร้อมแจ้งส่วนต่างที่เหลือ (Waste) — ถ้าความกว้างที่ต้องใช้เกิน 6 ม. ระบบแจ้งเตือน “เกิน 6 ม. — ต้องต่อผ้า” แทนการเลือกหน้าผ้าใบให้ผิด
  - **สำคัญ — ค่าเผื่อขึงผ้ายังเป็นสมมติฐาน:** ค่าเริ่มต้น 0.15 ม./ฝั่งทั้งด้านกว้างและยาว เป็นตัวเลขตั้งต้นเท่านั้น (ยังไม่ได้ยืนยันกับมาตรฐานหน้างานจริงของแผนก) แก้ไขได้อิสระต่อ Job แต่ละใบ
  - **ใบเบิกผ้าใบกับแผนก Store:** เบิกตามความยาวที่คำนวณได้ บวกเผื่อตัด/เศษเพิ่ม (%) ได้ตามจริง กดปุ่ม “ออกใบเบิกกับ Store” เพื่อบันทึกวันที่เบิก — แก้ตัวเลขความกว้าง/ยาว/ค่าเผื่อใด ๆ หลังเบิกแล้ว ระบบจะรีเซ็ตสถานะกลับเป็น “ยังไม่ได้เบิก” ให้อัตโนมัติ (กันหลงใช้ตัวเลขเก่า)
  - **ส่งมอบให้แผนกทอ:** แสดงวันที่ผ้าใบพร้อม (เจาะลายเสร็จ) เทียบกับวันที่แผนกทอเริ่มงานจริงตาม Master Plan (มักจะช้ากว่า เพราะแผนกทอต้องรอไหมย้อมเสร็จด้วย) — เมื่อเบิก Store แล้วให้ไปติ๊กยืนยัน “ผ้าใบสำหรับทอพร้อมแล้ว” ต่อในหน้า “ส่งแผนกทอ” เป็นหนึ่งใน 3 เงื่อนไขก่อนขึ้นทอ
  - บันทึกข้อมูลไว้ที่ `localStorage: siam-pattern-orders` แยกต่อ Design ID
- **แผนกทอ — จอทอรายวัน (แท็บ “แผนกทอ (จอทอรายวัน)” `weave-floor.js`)** — ตรงตามรูปแบบไฟล์ “รายงานการผลิตประจำวันพรมทอมือ” ที่แนบมา (สอบเทียบสูตรและคอลัมน์จากไฟล์จริงเดือนกันยายนที่อัปโหลด) แบ่งเป็น 4 แท็บย่อย
  - **เกต:** M/O จะโผล่ให้เลือกก็ต่อเมื่อติ๊ก “ผ้าใบสำหรับทอพร้อมแล้ว” ในหน้า “ส่งแผนกทอ” แล้วเท่านั้น — **ไม่บังคับรอไหมครบทุกสี** สีไหนพร้อมก่อนก็เริ่มบันทึกจอนั้นได้ก่อนตามที่ระบุมา
  - **1) ตั้งค่าขึ้นทอ:** กำหนดจอทอเบอร์ + เกรดทอต่อชิ้น (ค่าเริ่มต้นดึงจากใบวางแผนงาน แก้ต่อชิ้นได้ — M/O ที่มีหลายชิ้นแยกจอกันได้อิสระ) แนบรูปแบบพรมได้ (ย่อขนาดอัตโนมัติเหลือกว้างไม่เกิน 320px ก่อนเก็บ เพื่อไม่ให้ localStorage บวมเกินไป — **เก็บในเบราว์เซอร์เครื่องนี้เท่านั้น ไม่ได้ซิงก์ข้ามเครื่อง**) พร้อมตาราง “ไหมเข้าจอต่อวันต่อสี” แสดงสถานะไหมพร้อม/ยังไม่พร้อมต่อหม้อย้อม ยอดส่งมอบรวม และให้กรอกกิโลที่เข้าจอจริงต่อวันต่อสี ไม่ว่าสีนั้นจะพร้อมแล้วหรือไม่
  - **2) บันทึกประจำวัน:** เลือกจอ + วันที่ แล้วกรอกกะปกติ (ค่าเริ่มต้น 08.00–16.30 น. พัก 30 นาที) และกะโอที (ค่าเริ่มต้น 17.00–20.00 น.) แยกกัน — เวลาเริ่ม/เลิก/นาทีพักปรับได้อิสระทุกช่อง ระบบคำนวณ **ชั่วโมง/คน, คน×ชั่วโมงรวม (man-hours), ประสิทธิภาพ (ตรม./คน/ชม.)** ให้อัตโนมัติจากพื้นที่ที่ทำได้ ÷ คน×ชั่วโมง และ **“คงเหลือยกมา” ของแต่ละวันคำนวณสะสมจากพื้นที่รวมทั้งหมดที่ทอไปแล้วในวันก่อนหน้าโดยอัตโนมัติ** (ไม่ต้องกรอกเอง ตรงตามสูตรในไฟล์ Excel ต้นฉบับ) เลือกรายชื่อพนักงานต่อกะได้หลายคนจากทะเบียนพนักงานทอ/ตกแต่งเดิม (`localStorage: siam-workforce` — ทะเบียนเดียวกับหน้าใบวางแผนงาน)
    - **ช่างปรับปืน:** เพิ่มได้หลายรายการต่อวัน ระบุกะ (ปกติ/โอที) เวลาเริ่ม-เลิก (คำนวณระยะเวลาอัตโนมัติ) ชื่อช่างผู้รับผิดชอบ และเหตุผลที่ปรับ
    - **QC ต่อจอ:** บันทึกวันที่ตรวจ/ผู้ตรวจ/ผล (ผ่าน, ไม่ผ่าน, มีข้อสังเกต)/รายละเอียด ต่อจอ — ประวัติแสดงทั้งในหน้านี้และรวมทุกจอในหน้า **QC Dashboard** (นำทาง qcdash) พร้อมสรุป % ผ่าน/ไม่ผ่าน/มีข้อสังเกต
  - **3) หน้าจอทอ (ภาพรวม):** การ์ดของทุกจอที่ตั้งค่าไว้ เรียงตามเบอร์จอ แสดงรูปแบบพรม (ถ้าแนบ) M/O เกรด ชิ้น พื้นที่คงเหลือ และบันทึกล่าสุด/จำนวนคนทอล่าสุด — ใช้เป็นบอร์ดภาพรวมทุกจอที่กำลังทออยู่
  - **4) สรุป/ส่งออก/แจ้งเตือน:**
    - สรุปประจำวัน (เลือกวันที่ได้) รวมพื้นที่ปกติ/โอที/รวม ประสิทธิภาพ จำนวนคนทอ และแยกยอดตามเกรด (A/B/C/C+/D/D+/E/X/Z — ตารางเดียวกับท้ายชีตรายวันในไฟล์ต้นฉบับ)
    - **คำขอไหมเพิ่ม:** กดปุ่ม “ขอไหมเพิ่ม” ที่ตารางไหมเข้าจอ (แท็บตั้งค่าขึ้นทอ) กรอกจำนวนกิโล/เหตุผล/วันที่ต้องการ → รายการไปแสดงทั้งในแท็บนี้และ **หน้า Planning** (การ์ด “คำขอไหมเพิ่มจากแผนกทอ”) ให้แผนกวางแผนไปออกใบสั่งย้อมเพิ่มจริงในหน้าใบวางแผนงาน แล้วกลับมากรอกชื่อ “ผู้อนุมัติสั่งย้อม” เพื่อปิดคำขอ (`localStorage: siam-yarn-topup-requests`) — เป็นการติดตามสถานะ/ผู้รับผิดชอบเท่านั้น ไม่ได้สร้างรายการ Dye Order ใหม่ให้อัตโนมัติ
    - **ส่งออก Excel:** เลือกเดือนแล้วส่งออกเป็นไฟล์ `.xlsx` คอลัมน์ตรงกับไฟล์ “รายงานการผลิตประจำวันพรมทอมือ” ต้นฉบับทุกคอลัมน์ (วันที่/จอที่/M-O/คุณภาพ/เกรด/ชิ้น/พื้นที่ + บล็อกปกติ/โอทีอย่างละ 9 คอลัมน์ + รวม/วัน) พร้อมชีตสรุปแยกตามเกรด
    - **นำเข้า Excel:** รองรับไฟล์รูปแบบเดียวกัน (ทดสอบกับไฟล์ต้นฉบับเดือนกันยายนที่แนบมาจริงแล้ว) — จับคู่แถวกับ M/O ในระบบโดยเทียบเลขที่ M/O กับเลขที่เอกสารในหน้ารายงานขาย (`SalesEngine`) แถวที่จับคู่ไม่ได้จะถูกข้ามและสรุปจำนวนแถวที่นำเข้า/ข้ามให้หลังนำเข้าเสร็จ — รองรับเฉพาะตารางแบบแถวเดียวต่อวัน/จอ (ชีตสรุปรวม เช่น ชีต “SEP” ในไฟล์ต้นฉบับ) ยังไม่รองรับชีตพิมพ์รายวันแบบละเอียด (ที่มีแถวย่อยรายชื่อพนักงานแยกหลายแถวต่อจอ)
    - **แจ้งเตือนเข้า LINE:** สร้างข้อความสรุปประจำวันให้อัตโนมัติ พร้อมปุ่มคัดลอกข้อความและปุ่มบันทึกประวัติว่าส่งแล้ว — **ยังไม่ได้เชื่อมต่อ LINE Notify/Messaging API จริง** (ต้องมี Token ของบริษัทก่อนถึงจะส่งเข้ากลุ่ม LINE ได้จริง) ระบบนี้ทำได้แค่แต่งข้อความและเก็บ log การ “ส่งแล้ว” เท่านั้น
  - บันทึกข้อมูลไว้ที่ `localStorage: siam-weave-floor` (ข้อมูลจอ/วัน), `siam-yarn-topup-requests` (คำขอไหมเพิ่ม), `siam-loom-qc` (QC), `siam-line-notify-log` (ประวัติแจ้งเตือน)
- **แผนกทากาวตกแต่ง + ต้นทุนต่อ M/O (แท็บ “ทากาวตกแต่ง” `finishing.js`)** — ขั้นถัดจากแผนกทอ แบ่งเป็น 3 แท็บย่อย
  - **เกต:** ชิ้นจะโผล่ให้เลือกก็ต่อเมื่อแผนกทอกดปุ่ม “โอนให้แผนกทากาวตกแต่ง” ในหน้า “แผนกทอ → หน้าจอทอ (ภาพรวม)” แล้วเท่านั้น (ปุ่มนั้นกดได้ก็ต่อเมื่อทอครบ 100% ของชิ้นนั้นแล้ว) — บันทึกเวลาโอน (`transferredToGlueAt`) เป็นตัวกำหนดการส่งต่องานระหว่างสองแผนก
  - **1) รับพรม + ทากาว:** วันที่/เวลารับพรมจากแผนกทอ → ติ๊กปูพลาสติกก่อนทากาวหรือไม่ → เวลาเริ่ม/เสร็จทากาว → ขนาดพรมก่อนทากาว (กว้าง×ยาว คำนวณพื้นที่อัตโนมัติ) → เบิกผ้าตาข่ายกับ Store (หน้ากว้าง/ความยาวที่เบิก/ราคาต่อเมตรถ้ามี + ปุ่มออกใบเบิก) → เบิกกาวจาก Store ได้หลายชนิด (ตารางเพิ่ม/ลบรายการ ชนิดกาว/กิโล/ราคาต่อกิโล) → ทารอบแรก (กิโล+ชนิดกาว) และทารอบสอง (ถ้ามี กิโล+ชนิดกาวแยก) → **KPI ปริมาณกาว: มาตรฐาน = พื้นที่ก่อนทากาว × 2 กก. เทียบกับปริมาณจริง (รอบแรก + รอบสองถ้าทา) แสดงผลต่างเป็น % ให้ทันที** → ช่องหมายเหตุเผื่อเพิ่มรายละเอียดภายหลัง
  - **2) แห้ง + ตกแต่ง + QC:** ขนาดพรมหลังแห้ง (กว้าง×ยาว + พื้นที่หลังแห้ง) และติ๊กว่าได้มุมฉากหรือไม่ → วันที่/เวลาเริ่มตกแต่ง เกรด (ใช้ตาราง `FINISH_GRADES` เดียวกับใบวางแผนงาน เว้นว่าง = แนะนำอัตโนมัติจาก % ลายของแบบ) วิธีตกแต่ง (แต่งเรียบ/แกะลาย) และเลือกพนักงานที่แต่งพรมได้หลายคนจากทะเบียนเดียวกับแผนกทอ (`localStorage: siam-workforce`) → บันทึก QC ต่อชิ้น (วันที่ตรวจ/ผู้ตรวจ/ผล/รายละเอียด) ใช้ log เดียวกับแผนกทอ (ติดแท็ก `dept:"finishing"`) จึงไปรวมแสดงในหน้า **QC Dashboard** ได้ทั้งสองแผนกพร้อมกัน
  - **3) ต้นทุนต่อ M/O:** ตารางสรุปต้นทุนของทุก M/O ที่มีใบวางแผนงานแล้ว ใช้เลข M/O เป็นตัวกำหนด (ดูหมายเหตุขอบเขตด้านล่าง) รวม:
    - **ค่าไหม/ย้อม** — ดึงจากใบสั่งย้อมจริงที่บันทึกไว้ในใบวางแผนงานของ M/O นั้น (สูตรเดียวกับหน้าใบวางแผนงาน) หม้อสีใดยังไม่มีใบสั่งย้อมจะขึ้นเตือนแยกและไม่รวมเป็นต้นทุน (เพื่อไม่ให้เดาราคาที่ยังไม่ยืนยัน)
    - **ค่าแรงทอ+แต่ง** — ใช้สูตรเดิมของหน้าใบวางแผนงาน (พื้นที่ × ค่าแรงตามเกรดทอ + พื้นที่ × 400 บาท/ตร.ม. สำหรับแต่ง/ทากาว) **หมายเหตุ: หน่วยค่าแรงนี้เป็นค่าที่ตั้งไว้ตั้งแต่หน้าใบวางแผนงาน ยังไม่ได้ยืนยันกับฝ่ายบัญชี**
    - **ค่าผ้าตาข่าย+กาว** — รวมจากราคาที่กรอกจริงในแท็บ “รับพรม + ทากาว” (ถ้าไม่กรอกราคา = 0 ไม่ได้เดาให้)
    - **ค่าขนส่ง + ค่าพนักงานเพิ่มเติม** — กรอกได้เฉพาะเมื่อ M/O นั้นขายในประเทศ (`market: DOMESTIC` จากหน้ารายงานขาย) เท่านั้น ถ้าส่งออกต่างประเทศจะไม่รวมค่านี้ (ซ่อนช่องกรอกให้เลย)
    - **รายการต้นทุนอื่น ๆ** — ตารางเพิ่ม/ลบรายการชื่อ+จำนวนเงินได้อิสระไม่จำกัด สำหรับต้นทุนที่ยังไม่ได้กำหนดหมวดไว้ล่วงหน้า (กรอกเพิ่มทีหลังได้ตามที่ระบุ)

## ใบส่งสินค้า (Delivery Note) + Marks & Nos

หน้าใหม่ “ใบส่ง/Marks&Nos” (อยู่ในขั้น Sales ของ workflow, ไฟล์ `shipping.js`/`shipping.css`) ทำตามตัวอย่างใบส่ง + ป้าย Marks & Nos ที่แนบมา:

- **ดึงรายการจาก M/O และ SO ตัวอย่างที่มีอยู่แล้วในหน้ารายงานขาย** (ค้นหาด้วยเลข M/O/SO, ชื่อลูกค้า หรือโปรเจกต์) มารวมเป็น “ใบส่ง” เดียวกันได้หลายรายการ โดยยึด **เลขที่ INVOICE เป็นตัวตั้ง** (ตรงกับตัวอย่างที่แนบ: M/O 109–115/26 รวมอยู่ใน INVOICE 058/26 ใบเดียว) — เมื่อกรอกเลข Invoice แล้ว ระบบจะย้อนเขียนกลับเข้าช่อง “INV No.” ของ M/O/SO นั้นในหน้ารายงานขายให้อัตโนมัติด้วย
- แต่ละรายการ (M/O/SO) แก้ไข **MARKS / MEASURMENT / NOTE** ได้อิสระในใบส่ง โดยไม่กระทบข้อมูลเดิมในหน้ารายงานขาย (ค่าเริ่มต้นของ MARKS ดึงมาจากช่อง Project ให้อัตโนมัติ แก้ได้)
- แต่ละรายการแตกเป็น **กล่อง/พาเลทได้หลายกล่อง** (ปุ่ม “+ กล่อง” ที่แต่ละแถว) สำหรับกรณีสินค้าชิ้นเดียวกันแบ่งส่งหลายกล่อง (เช่นตัวอย่าง: M/O 102/26 แบ่งเป็นกล่อง No.1 (ชิ้นที่ 1–5) และกล่อง No.2 (ชิ้นที่ 6–10)) — เลข **NO.** ของกล่องเรียงอัตโนมัติตามลำดับทั้งใบ Invoice ไม่ต้องนับเอง คอลัมน์ “ROLL NO.” ในตารางรายการจะสรุปช่วงเลขกล่องของแต่ละ M/O/SO ให้อัตโนมัติจากกล่องที่สร้างไว้
- **พิมพ์ได้จากในแอปทันที** (ไม่ต้องออกไฟล์แยก) ด้วยหน้าต่างพิมพ์ทับเต็มจอแบบเดียวกับฟอร์ม M/O A3 เดิม — ปุ่ม “พิมพ์ใบส่ง” ออกตารางใบส่งสินค้าขนาด A4 ตามรูปแบบ INV.NO/CUSTOMER/ROLL NO./M-O/MARKS/MEASURMENT/NOTE พร้อมหมายเหตุการแพ็คสีแดงด้านล่าง และปุ่ม “พิมพ์ Marks & Nos” ออกป้ายกำกับหีบห่อทีละกล่อง (MARKS & NOS, HANDLE WITH CARE, ที่อยู่ผู้รับ, NO., MADE IN THAILAND, REFERENCE, รายละเอียดสินค้า, SIZE, M/O, *INVOICE*) — กด “พิมพ์ / บันทึกเป็น PDF” ในแถบด้านบนเพื่อพิมพ์จริงหรือ Save as PDF ได้เลย
- ข้อมูลใบส่งทั้งหมดเก็บที่ localStorage คีย์ `siam-shipments` แยกจากข้อมูล M/O/SO เดิม ลบใบส่งได้จากหน้ารายการ (มีขอความยืนยันก่อนลบเพราะกู้คืนไม่ได้)
- **ช่องกรอกที่ควรทราบ:** ช่อง “ขนาด/DIM” ของกล่องให้กรอกเฉพาะตัวเลข (เช่น `50X87X50CM.`) ไม่ต้องพิมพ์คำว่า “DIM:” นำหน้าเอง เพราะระบบใส่คำนำหน้าให้ตอนพิมพ์ป้ายอยู่แล้ว

## ทะเบียนรายชื่อพนักงาน (เพิ่ม/ลบได้ทุกแผนก) + นำเข้า/ส่งออก Excel

ทุกแผนกที่มีการเลือกพนักงานทำงาน (เจาะลาย/ขยายลาย/ปั๊มผ้า, ทอ, ทากาวตกแต่ง) มีกล่อง “รายชื่อพนักงาน…” ให้เพิ่ม/ลบรายชื่อได้เองในหน้าเว็บ ไม่ต้องแก้โค้ด:

- **ทะเบียนมี 2 ชุด เก็บแยกกันใน localStorage:** `siam-workforce-pattern` (แผนกเจาะลาย/ขยายลาย/ปั๊มผ้า — จัดการได้ที่หน้า “เจาะลาย/ปั๊มผ้า”) และ `siam-workforce` (ใช้ร่วมกันระหว่างแผนกทอกับแผนกทากาวตกแต่ง เพราะพนักงานกลุ่มนี้มักทำงานร่วมกันสองแผนก — จัดการได้ทั้งที่หน้า “ใบวางแผนงาน” (ข้อ 6), หน้า “แผนกทอ” และหน้า “แผนกทากาวตกแต่ง” พร้อมกัน แก้ที่ไหนก็เห็นผลทันทีทุกหน้าเพราะเป็นทะเบียนเดียวกัน)
- แต่ละกล่องมีปุ่ม **“+ เพิ่มรายชื่อ”** (พิมพ์ชื่อแล้วกดปุ่มหรือกด Enter) และปุ่ม **“×”** ที่ท้ายชื่อแต่ละคนสำหรับลบ กันชื่อซ้ำอัตโนมัติ (เทียบแบบไม่สนตัวพิมพ์เล็ก/ใหญ่) — ลบชื่อออกจากทะเบียนไม่กระทบข้อมูลที่บันทึกไปแล้ว (ชื่อที่เคยถูกเลือกในบันทึกประจำวัน/ใบสั่งเก่ายังอยู่ครบ เพียงแต่จะไม่ขึ้นให้เลือกซ้ำอีก)
- **ส่งออก/นำเข้า Excel:** ทุกกล่องมีปุ่ม “ส่งออก Excel” (ดาวน์โหลดรายชื่อปัจจุบันเป็นไฟล์ `.xlsx` 2 คอลัมน์ “แผนก” / “ชื่อ-นามสกุล”) และช่อง “นำเข้าจาก Excel” — อัปโหลดไฟล์ที่มีคอลัมน์เดียวกันได้จากหน้าไหนก็ได้ ระบบจะอ่านคอลัมน์ “แผนก” ของแต่ละแถวแล้วแยกใส่ทะเบียนที่ถูกต้องให้อัตโนมัติ (ไม่ว่าจะอัปโหลดจากหน้าเจาะลาย/ปั๊มผ้า หรือหน้าทอ/ตกแต่ง ก็กระจายเข้าทะเบียนที่ตรงกันเสมอ) แถวที่เว้นคอลัมน์แผนกว่างไว้จะถือว่าเป็นแผนกของหน้าที่กำลังอัปโหลดอยู่ ชื่อซ้ำกับที่มีอยู่แล้วจะถูกข้ามให้อัตโนมัติ
- ไฟล์ `แบบฟอร์มนำเข้ารายชื่อพนักงาน.xlsx` (ส่งมอบแยกต่างหาก) เป็นแบบฟอร์มเปล่าพร้อม dropdown เลือกแผนกและคำแนะนำการใช้งานในชีต “คำแนะนำ” — ลบแถวตัวอย่าง (มีคำว่า “ตัวอย่าง” กำกับ ระบบจะข้ามให้อัตโนมัติแม้ลืมลบ) แล้วกรอกรายชื่อจริงก่อนนำเข้า
- ยังไม่มีทะเบียนพนักงานแยกสำหรับแผนกอื่น (เช่น แผนกย้อม/Store) เพราะหน้าจอเหล่านั้นยังไม่มีช่องเลือกพนักงานในระบบปัจจุบัน — แจ้งได้หากต้องการเพิ่ม

เว็บแอปนี้ (root ของ repo) กับระบบ **Production Plan & QC Siam Carpets** เดิม (เว็บไซต์เดิมที่ `https://walaipanno-sudo.github.io/Qc-Dashbord/`) เป็น **คนละระบบกัน คนละสถาปัตยกรรม** — ตามคำขอให้เก็บทั้งสองไว้ใน repo เดียวกันแบบคนละหน้า/โฟลเดอร์ จึงคัดลอกซอร์สของระบบเดิม (จาก repo `walaipanno-sudo/Qc-Dashbord`, commit `1627c52`) มาไว้ที่โฟลเดอร์ย่อย `qc-dashboard/` โดย **ไม่แตะไฟล์ที่ root** เลยสักไฟล์:

- `qc-dashboard/index.html` — หน้าเว็บของระบบเดิม (ไฟล์เดียวกับที่ deploy อยู่บน GitHub Pages ของ repo เดิมทุกประการ) ดึงข้อมูลจาก **Google Sheets ผ่าน Google Apps Script** (คนละฐานข้อมูลกับแอปนี้ที่ใช้ `localStorage` ในเบราว์เซอร์) — เมื่อ deploy ขึ้น GitHub Pages จริงจะเรียกใช้งานได้ตามปกติเหมือน URL เดิมทุกประการ เพียงแต่ path เปลี่ยนเป็น `<เว็บไซต์ siamcarpets>/qc-dashboard/`
  - ทดสอบแล้วว่าโหลดหน้าและ layout ครบถ้วนถูกต้องที่ path ใหม่นี้ (ไม่มี absolute path ที่จะพังตอนย้ายเข้าโฟลเดอร์ย่อย) — ส่วนการเชื่อมต่อข้อมูลจริงไปยัง Google Sheet ต้องทดสอบอีกครั้งบนเว็บจริงหลัง deploy (ในนี้ทดสอบได้แค่ว่าโครงหน้าเว็บขึ้นถูก เพราะ sandbox นี้ไม่มีสิทธิ์ออกอินเทอร์เน็ตไปหา Google)
- `qc-dashboard/apps-script/` — ซอร์สฝั่ง backend (Google Apps Script `Code.js`, frontend สำรอง `index.html`, manifest) เก็บไว้เพื่ออ้างอิง/พัฒนาเท่านั้น ไม่ได้ทำงานอะไรบน GitHub Pages (Apps Script deploy แยกอยู่ที่ Google ตามเดิม ไม่เกี่ยวกับ repo นี้)
- `qc-dashboard/scripts/`, `qc-dashboard/README.md`, `qc-dashboard/HANDOFF.md` — คงไว้ตามต้นฉบับเพื่อให้พัฒนาต่อได้เหมือนเดิมถ้าย้ายซอร์สมาทำต่อที่นี่
- **ไม่ได้คัดลอก** `.github/workflows/validate-apps-script.yml` มาด้วย เพราะ workflow นั้นอ้าง path แบบ root (`apps-script/...`) ของ repo เดิม ถ้าย้ายมาทั้งดุ้นจะพังเพราะ path เปลี่ยนเป็น `qc-dashboard/apps-script/...` — ถ้าต้องการ CI ตรวจ syntax ให้ setup ใหม่แยกต่างหากทีหลัง
- ไม่มีการฝัง API key/Secret ใด ๆ ในไฟล์ที่คัดลอกมา (Supabase URL/anon key ผู้ใช้กรอกเองผ่านหน้าตั้งค่าแล้วเก็บใน `localStorage` ของเบราว์เซอร์คนนั้น, ค่า `LINE_CHANNEL_ACCESS_TOKEN`/`DASHBOARD_WRITE_KEY`/`SUPABASE_SERVICE_ROLE_KEY` ตั้งอยู่ที่ Apps Script Project Settings ของ Google ไม่ได้อยู่ในซอร์สที่ commit) — URL ของ Apps Script Web App (`DEFAULT_GAS_WEB_APP_URL`) เป็นค่าเดิมที่เปิดเผยอยู่แล้วในเว็บไซต์เดิมที่เป็น public repo อยู่ก่อนแล้ว ไม่ใช่ข้อมูลใหม่ที่เพิ่งเปิดเผย
- เพิ่มลิงก์ **“แผน+QC (ระบบเดิม) ↗”** ที่แถบเมนูบนของหน้าแรก เปิดหน้า `qc-dashboard/index.html` ในแท็บใหม่ (ไม่ได้รวม view เข้าเป็นส่วนหนึ่งของ SPA นี้ เพราะเป็นคนละระบบจริง ๆ ทั้ง data source และ backend)
